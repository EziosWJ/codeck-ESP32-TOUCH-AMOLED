# Codeck RDP 串口烧录

用中文逐步引导用户，后台完成构建、烧录和校验。用户请求创建或解释技能时，只处理技能；只有用户请求烧录时才写设备。此流程不负责恢复出厂或修改固件功能。

## 项目和串口

- 从本技能所在仓库执行；目标为 Waveshare ESP32-S3-Touch-AMOLED-1.43（不是 1.43C），16 MB Flash，ESP-IDF 6.1。
- 本机工具路径和操作命令见 [Windows 命令](references/windows-commands.md)，执行前读取。
- 最近成功端口为 COM5，其 RDP 映射为 `\Device\RdpDrPort\;COM5:1\tsclient\COM5`。传给 esptool 的是 `COM5`，不是映射路径。优先使用用户本次指定的端口；没有指定且上下文不能确定时询问，不轮流向其他端口写入。
- RDP 端口可能不出现在 pyserial 或 Win32_SerialPort 枚举中。枚举缺失不能证明不可用。若受沙箱限制无法打开，按执行工具的权限流程重试；不要把权限问题直接归因于用户设备。
- 最近设备 MAC 为 `28:84:85:b0:db:34`，仅用于识别这台设备，不要求所有设备都有相同 MAC。发现目标型号或用户指定设备不符时先解决，不继续写入。

## 按顺序执行

1. **准备固件。** 简述端口、固件来源及烧录范围。检查仓库的现有改动，保留用户代码。使用 `Build-Firmware.ps1` 构建当前源码，检查退出码和分区容量检查结果；构建失败就修复或报告，不能悄悄烧录旧文件。如果用户明确选定现成固件，则核实其配套构建元数据，不强行替换。
2. **检查写入计划。** 运行 `Invoke-RdpFlash.ps1 -Port COM5 -DryRun`。默认 full 写入生成元数据指定的 bootloader、分区表和应用；已确认同一设备的 bootloader、分区布局未变时可用 `-Mode app`，这也是最近修复固件的方式。脚本对本项目当前布局设有保护，布局变化须先检查实际设备及 NVS 范围再调整，不能绕过保护盲刷。普通写入保留 NVS；不执行 `erase-flash`，不自动清除配网记录。
3. **让用户进入下载模式。** 提示：“请关闭占用 COM5 的串口监视器；按住 BOOT，短按 RESET，再松开 BOOT。准备好后告诉我。” 用可用的用户输入工具询问并等待实际回复；没有工具时结束本轮等待回复。用户已明确说进入下载模式时直接继续，不能再次要求相同步骤。等待时间经过不等于准备完成。
4. **烧录。** 使用同一计划去掉 `-DryRun` 执行。RDP 自动复位此前反复 Write timeout，所以手动下载模式后固定 `--before no-reset`；结束使用 `--after hard-reset`。不先尝试一轮已知不可靠的自动进入下载模式。轮询同一个执行会话直到退出；每次等待不超过 60 秒，工作期间至少每 60 秒更新进度。
5. **校验。** 各写入段出现 `Hash of data verified.` 且进程退出码为 0 才报告“写入校验通过”。保留写入范围、端口、退出码等可核查结果。`Failed to get VID/PID` 对 RDP 很常见，单独出现并非失败；连接或 stub 阶段可能安静 20–40 秒，不能因此中断。若退出非 0，不报告成功。
6. **确认正常启动。** `Hard resetting via RTS pin` 不代表 RDP 已让应用启动。提示：“烧录校验通过。请确认屏幕是否正常；若仍停在下载状态或黑屏，请松开 BOOT，短按 RESET，必要时断电重启。” 等用户反馈。若 USB 重新枚举导致端口变化，询问新端口。屏幕或可靠启动日志确认前，只说写入成功，不声称设备功能全部正常。
7. **按本次改动验收。** 配网修复时让用户按屏幕上的新密码重新连接 Codeck 热点，访问 `http://192.168.4.1`，区分“热点连接成功”“网页可达”和“API 验证成功”。普通烧录则确认屏幕和本次相关功能。最后报告构建、写入、启动、实际验证结果及剩余问题。

## 失败后处理

- 端口被占用：关闭自己的串口采集会话，提示用户关闭监视器；不要结束无关进程。
- `Write timeout` 或无法握手：检查实际下载模式和当前端口；每次有实际条件变化后重试一次，连续失败就等待用户操作或排查连接，不能同条件无限重刷。RDP 连接仍不稳定时可在重新确认下载模式后降为 `-Baud 115200`。
- 中途写入失败：说明应用可能未完整写入，修复链路后重刷同一固件；不要以整片擦除作为兜底。
- 重启仍黑屏：采集启动日志并查 panic、内存/显示初始化等错误，不先恢复出厂。此前黑屏来自 LVGL 内存分配，热点网页拒绝连接来自 HTTP 服务启动时序；它们是历史线索，不应自动套用到新故障。
- 采集日志时读取 [Windows 命令](references/windows-commands.md) 的 RDP 限制。没有采集到日志不能证明没有崩溃。凭据、Wi-Fi 密码和 Authorization 不写进日志或输出；不采集无限日志。

整个过程由代理管理用户交互关卡，脚本不会替用户确认已按键，也不会自动重复刷机。
